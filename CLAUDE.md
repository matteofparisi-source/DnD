# CLAUDE.md

**DnD Slop** is a D&D 2024 character sheet and Eberron campaign journal for one character, an Artificer (Artillerist) from *Eberron: Forge of the Artificer*.
Stack: plain HTML/CSS/JavaScript (ES modules) installable PWA. No build step, no dependencies, no backend; works offline.
Target devices: Android (Redmi 15, Chrome) and Windows 10/11 (Edge/Chrome). README.md is the user-facing feature list and install guide; don't repeat it here.

## Agent setup
- `.claude/settings.json` sets the main session (the coordinator) to `claude-opus-5-5`. It sets subagents to `claude-sonnet-5-5` through `CLAUDE_CODE_SUBAGENT_MODEL`, with `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` so built-in agents (Explore, Plan) use Sonnet too.
  - unverified: the FORCE variable needs Claude Code 2.1.257+ per the docs. It was not tested in this repo.
  - `/model`, `--model`, `ANTHROPIC_MODEL` or `.claude/settings.local.json` can override the main model.
- Operative agents live in `.claude/agents/`: `implementer` (code/data edits), `tester` (local server + Playwright checks), `rules-researcher` (web facts with sources), `reviewer` (diff review against this file). All pin `model: claude-sonnet-5-5`.
- The coordinator plans, splits work, delegates to these agents, checks their reports, and does the commits/pushes itself. Agents don't commit.
- Model IDs are pinned, not aliases. When a newer Opus/Sonnet ships, update `.claude/settings.json`, every file in `.claude/agents/` and this section.

## Run and check locally
- Serve the repo root: `python3 -m http.server 8000`, then open http://localhost:8000. Opening `index.html` via `file://` fails (ES modules; the service worker isn't registered on `file:`).
- Tests live in `tests/` (no package.json; Playwright is resolved from the environment). Details in `tests/README.md`.
  - `node tests/unit.mjs`: pure Node, ~1 s: syntax of all scripts, data integrity, `APP_VERSION` == `CACHE`, `ASSETS` coverage, manifest/icon sizes, `normalize()` migrations, snapshots.
  - `node tests/run.mjs [--only name] [--headed] [--list]`: unit plus 14 Playwright suites in `tests/e2e/` (own static server, Pixel 7 plus one 1366x768 check, stubbed Drive, update banner, offline, a11y; ~150 s). axe-core is used only if installed.
  - Run both before every commit; add a test in `tests/e2e/` for a new feature. Seed localStorage with `page.addInitScript` (the app saves on `pagehide`).

## State and data
- One state object (`version`, `character`, `campaign`, `sessions`, `journal`, `ui`).  `ui` defaults: `tab` 'combat' (new users), `theme` 'dark', `sub`, `haptics` true (vibration toggle in Character > Campaign & data), `trackWeight` true (Equipment page switch: hides weight fields and the carried counter), `drive` `{connected, folderId, fileId, lastSyncAt, lastRemoteModified, syncedHash, backupDay, needsConfirm}` (local-only Drive metadata: not in the Drive file or in `backupFile()`, kept on import/restore/Drive download, reset by Delete everything). `character.concentration` is `{ id, name }` (empty name = none). It's saved as JSON in localStorage under the key `dnd-companion-v1`. Don't rename the key: existing devices would lose their data.
- Inputs bind with `data-bind="dot.path"`. A `#id` segment selects an array item by `id` (e.g. `character.items.#abc.name`).
  - The input handler writes the value, saves (debounced, 250 ms) and calls `refreshDerived()`.
  - Derived numbers live in `<span data-calc="key">` elements, computed by `calc()`.
- **All derived numbers go through effects.js** (`FX()` in app.js, `breakdown(key)`): never compute a modifier, save, DC, AC or speed from `character.abilities` directly. `character.abilities` holds BASE scores; use `abilScore(k)` (total) or `am(k)` (modifier). `FX()` is memoized and reset by `setPath`/`persist`/`render`/`refreshDerived` and at the end of the task. `saveBonus`/`initBonus`/`acMisc` are the "Manual" parts. With `acAuto` or `hp.auto` off the typed value is used as is (no effects).
- Choices are stored as ids, never as copies of data: `character.spells` maps spell id → `'prepared'`/`'known'`; `plans.known` maps plan id → true; `feats` is a list of `{id, featId, level, notes, choices:{}, effects:[]}`.
  - Ids come from names (`slug`, or the same regex in plans/feats), so **renaming a data entry orphans saved choices** unless you migrate them.
  - "Always prepared" is computed (`alwaysPrepared()`), not stored.
- Schema v3: `attacks[].damages` is a list of `{id, dice, type}` (flat bonus and ability mod go on the first). Items carry `qty`, `weight`, `acBonus` and a `weapon`/`armor`/`shield` sub-object by type (`ensureItemData()` in store.js adds them, parsing "+N" from the name); rarity `Mundane` items show only on the Equipment tab. `character.acAuto`/`acMisc`: AC is computed by `acInfo()` from equipped items; `ac` is used only when `acAuto` is false. `inspiration` stays in the data but has no UI.
- `render()` puts `cond-<name>` and `exh-<n>` classes on `<body>`; CSS draws the vignettes and hero effects from them. The status strip under the header lists active conditions (on Combat the same chips sit in the conditions row and open the conditions sheet). Combat page order: header plates, death-saves card (top at 0 HP, else low), glance (Initiative, Speed and Max HP with "+" breakdowns, except Initiative whose "+" is on Roll reference; Concentration row), conditions row, Active spell effects, Resources, Roll reference, Eldritch Cannon, then collapsed `<details>` blocks (Edit defense, Edit attacks; open state in `openBlocks`). Taking an Incapacitating condition (any whose `CONDITION_EFFECTS` text says Incapacitated) ends concentration.
- **Undo:** `snap()` pushes `{id, raw}` (JSON of character + sessions + campaign + journal, not ui) onto an in-memory stack (max 20, lost on reload). Call it BEFORE every mutating action; `mutate()` does snap, change, save, render, `buzz()` and an Undo toast. A no-op action drops its snapshot (`dropIfNoop()`, also checked in `toast(..., {undo:true})`) and shows no toast. Each toast's Undo carries its snapshot id and only undoes that action; a newer `snap()` removes older Undo buttons. The stack is cleared on typing into any `data-bind` field, backup import, storage sync and reset, so Undo can never revert typed text. Deletes have no `confirm()`.
- **Bottom sheet:** `openSheet(kind, opener)` / `closeSheet()` / `renderSheet()` render into `#sheet-root` (outside `#view`, which gets `inert`). Kinds live in the `SHEETS` map (damage, heal, cannonhp, hd, rest, cond, conc, slot, detonate, coin, generic, quick, confirm, choices). `confirmSheet(opener, {title, text, ok, run})` is the Cancel / Continue dialog for over-limit spells/plans/crafting and unmet feat prerequisites. Sheet state is the module variable `sh`; focus returns to the opener. Use sheets, not `confirm()`/`prompt()`. Sheet text inputs use `data-sh` (`text`, or `f` + `data-field` for the quick-add form in `sh.f`). Keypad and d8 grid buttons are plain `data-action` buttons. Real dice only: no rolling or `Math.random` anywhere (`uid()` uses Web Crypto).
- **Dock:** `dock()` is the fixed Damage / HP / Heal / Rest bar on Combat (`body.has-dock`). Hot paths (pips, HP, cannon HP) update in place through `refreshDerived()`/`syncPips()` instead of a full render; HP and resource numbers use `data-calc` keys (`hpcur`, `slotleft:i`, `useleft:key`, `cannonhp:id`...).
- `rest()` was replaced by `applyRest(c, kind, opts)` (mutates the given character) and `restSummary()` (runs it on a copy to list the changes shown in the Rest sheet).
- **Spells page:** `F('spells').view` is `mine` (default; selected spells grouped by level) or `all` (full list, filters). Spell cards and item/feature cards are `<details>`; bodies marked `data-lazy` (spell body, item Edit block) are inserted on open and removed on close (`LAZY` map in the toggle listener). Inventory: `itemCard(i, 'equip'|'magic')` is collapsed (Equipped/Attuned toggles, qty stepper); `attuneBar()` shows read-only slot pips; coins open the `coin` sheet (keypad, Add/Spend, undoable).
- Damage components are edited with `damageEditor(path, list)` and the `addDamage`/`removeDamage` actions (`data-path` is the list path).
- Export: `backupFile()` makes a JSON file (the whole state, journal and voice included), offered through the Web Share API (when files can be shared) or as a download. Import: JSON → checked → `confirmSheet` → snapshot → `normalize()` → replaces all state. A `storage` event listener keeps open tabs in sync.
- **Schema v4:** `journal` = `{npcs, places, factions, quests}`; every entry has `id`, `tags` (lowercase, deduped by `cleanTags`), `notes`, `createdAt`/`updatedAt` (ISO; `touch()` bumps the latter on edits). npc `{name, role, faction, attitude, location}`, place `{name, kind, region}`, faction `{name, attitude, goals}`, quest `{title, status, giver, reward, steps:[{id,text,done}]}`; `attitude` friendly|neutral|hostile|unknown, `status` active|done|failed|paused. Sessions got `tags`. `character.voice` = `{personality, ideals, bonds, flaws, quirks, goals:[{id,text,done}], lines:[{id,text}]}`; `bio` is kept (shown in Voice > Background notes). `normalizeV4()` coerces everything (idempotent) and copies `bio.personality` into `voice.personality` only when migrating from < 4. Factories: `newNpc/newPlace/newFaction/newQuest` in store.js.
- **Journal** (Journal section, sub-tabs Sessions | NPCs | Places | Factions | Quests; tab keys `journal`, `npcs`, `places`, `factions`, `quests`): config in `JK`, one set of builders for all kinds (`jCard`, lazy `jBody`, `jList`, `jPage`). Cards are `<details data-jcard="coll:id">`; open ids in `openCards`, body inserted on open. Per-list search/tag chips use `F(coll)` (`matchQ` on `jText()`); sort newest first (`createdAt`), quests active first, sessions by number. The global `#jsearch` (module vars `jq`, `jtag`) swaps the page body for grouped `jResults()`; `goEntry('coll:id')` jumps to a card (also used by the toast Open button, `voice:` opens the Voice tab). Tags use `tagsEditor()` + `addTag`/`removeTag`; steps and goals use `checklist()` + `listAdd`/`listRemove` (`data-path` is the array path). Badges always carry text. Textareas with `data-grow` auto-size (`grow()`).
- **Quick add:** the header ＋ (`data-kind="quick"`) opens the `quick` sheet: `QUICK` table, `qaPick`/`qaBack`/`quickSave`. Session note appends a `[HH:MM]` line to today's latest session (created as "Session N" if none is dated today, local date via `localDay()`); line goes to `character.voice.lines`. Saves through `mutate(..., {open: 'coll:id'})`, so the toast has Undo and Open. Closing the sheet keeps typed text as an in-memory draft per form kind (`qaDraft`).
- **Snapshots:** second localStorage key `dnd-companion-snapshots`, newest first, entries `{id, at, reason, kind, data}` (data = JSON string) via `takeSnapshot(state|json, reason, kind)`. Kinds and retention (eviction only within a kind): `daily` 1 (first launch of a local day; marker key `dnd-companion-snapday`), `rest` 1 (before a long rest), `important` 3 (before a version upgrade, import, restore, delete everything; unreadable data). It returns false instead of throwing when storage is full; import/restore then warn in the confirm sheet (`replaceWithSafety`: Download current data first / Continue anyway / Cancel) and a long rest shows a warning toast. `save()` on a quota error drops snapshots (oldest daily/rest, then oldest important) and retries; every save goes through `saveNow()` (updates `#saveStatus`). **Unreadable data:** if `load()` cannot parse/normalize, the raw string is kept as an important snapshot "Unreadable data", defaults are used, nothing is written to the main key until the user changes something (`releaseSave()` in `persist()`), and a toast says so. Card in Campaign & data: Restore (keeps `ui`) and Download. Delete everything snapshots first and keeps snapshots. Ids are sanitized to `[A-Za-z0-9_-]` in `normalize()` (`fixIds`, unique per list).
- **Feats apply automatically:** Take opens the `choices` sheet when the feat has `choice` effects (`choiceSlots`, `cleanPicks`, `chPick`; Cancel = not taken; one pick = string, several = list in `entry.choices[key]`); otherwise it is taken at once. Taken rows show "Applied automatically" (`featApplied`) with source label and Edit choices (same sheet, `editChoices`/`choicesGo`); the manual Effects editor stays. `featSpells()` (cached per Fx object) feeds `alwaysPrepared()`: spells granted `always`, plus "Spells of the Mark" (`expanded`) which join the Artificer list while the Mark feat is taken (always prepared only with Potent Dragonmark, and only up to the spell level you can cast; the data cannot tell which Mark a Potent belongs to, so it covers every Mark taken). Granted spells show in My spells and as card tags (feat, free cast, own DC/attack when the ability is not INT). Spells page Feat filter (`F('spells').feat`: '' = All, 'none' = spells with no feat at all, or a feat id; a feat-bound Artificer spell matches its feat and All, not None) works in All spells only. `cleanEffect(x, strict)`: spell/use/choice effects are whitelisted and slugged; resolved feat effects use strict mode (an invalid pick drops the effect). Feat notes stay terse own-words fragments (110 chars max, unit-tested). Free casts and `use` effects are in the Resources card under the feat name, stored in `character.uses['feat:<entryId>:<key>']` (long rest clears all, short rest only `reset: 'short'`; `usesMax()`/`calc('useleft:...')` read `FX().uses()`; dropping the feat deletes its keys).
- **Schema v5:** items and taken feats carry `effects: [{id, type, target?, value?, cond?, text?}]` (items also keep `acBonus`, counted as an `ac` effect, and `catalogId`/`fxSrc` = where catalog effects came from; no version bump, `normalizeV5()` cleans them); `character.buffs` = ids of switched-on non-concentration spells (a long rest clears them). Undo/Drive/backup carry them like any character field. `normalizeV5()` coerces effects (drops unknown types, clamps numbers; `spell`/`use`/`choice` pass through; feat `choices` values are strings or string lists, 80 chars max).
- **Any change to the data shape needs a migration** in `normalize()`, plus a `SCHEMA_VERSION` bump (now 5). The v1→v2 step (generic sheet → Artificer), `normalizeV4()` and `normalizeV5()` are the patterns. `merge()` fills in missing fields from `defaultState()`, so purely additive fields need only a default.

## Google Drive sync
- Local save is always first; Drive mirrors it: folder `DnD Slop` -> `dnd-slop-save.json` + `dnd-slop-YYYY-MM-DD.json` daily backups (newest 7 of the app's own; `dnd-slop-conflict-*` and other files are never pruned). The file is `backupFile()` content (no `ui.drive`) plus `savedAt` and `device`; those two are dropped on download. A 404 on a stored id triggers a search by name, then recreation.
- Dirty = hash of state without `ui` differs from `ui.drive.syncedHash`. Auto sync only runs with a valid token: 15 s debounce (min 15 s gap), immediately after a long rest or a quick-added session note. **Never request a token without a tap** (an expired pass shows the "Sync to Drive" button). Remote newer + clean -> silent download; remote newer + dirty -> conflict sheet (tap-started) or a "review" button (auto). Every Drive download takes an 'important' snapshot "Before Drive download".
- **Never store the token** (not in localStorage, state, backups or the Drive file). Only https googleapis URLs; validate downloads with `isBackup()` before `normalize()`.
- Tests: no real Google account. Playwright stubs `window.google.accounts.oauth2` (`initTokenClient`/`revoke`) via `addInitScript`, routes `accounts.google.com` to an empty script and `https://www.googleapis.com/**` (including OPTIONS preflight) to an in-memory fake Drive. Hooks read only if present: `window.__driveDebounceMs`, `__driveBackoffMs`, `__driveSignInTimeoutMs`, `__drivePendingVisMs`, `__driveGsiTimeoutMs`.
- Sign-in is two taps when Google's script is not loaded yet (first tap prepares, button becomes "Sign in with Google" / "Sign in to sync"; `requestAccessToken()` is called synchronously in the second tap's handler, never after an await). Tests record that in the stub (`__ratLog`).

## Service worker rules
- `sw.js` is network-first: online users get new files without a bump. Offline users and freshly installed apps get the cached copy.
- The browser only reinstalls the worker when `sw.js` itself changes. So **bump `CACHE` (`ledger-vN`) whenever any cached asset changes, and bump `APP_VERSION` in `js/version.js` to the same value in the same commit**. That refreshes the precache and deletes old caches.
- Install precaches with `cache.addAll` of `Request(url, {cache: 'reload'})` (atomic: a failed file means no half-updated set). The worker still does skipWaiting + claim; app.js shows a persistent "DnD Slop was updated / Reload" banner (`showUpdateBanner`, `#update-banner`) on `controllerchange`, only if the page already had a controller (not on first install). It never reloads on its own, is hidden while a sheet is open (CSS), and Reload calls `save(state)` (not `saveNow()`, which would release the unreadable-data hold). Returning to the app triggers `registration.update()` at most every 30 min.
- Add every new file the app loads to `ASSETS`, or it won't be available offline.

## Conventions seen in the code
- No frameworks. Views are template-string functions returning HTML. Re-rendering replaces `#view.innerHTML`, and `render()` restores focus and scroll.
- Escape every user or data string with `esc()` before putting it into HTML.
- Buttons use `data-action="name"` plus `data-*` args, handled in the `actions` object through one delegated click listener.
- Fields that change structure use `data-rerender`. Checkboxes and selects re-render automatically on `change`.
- **Navigation:** `SECTIONS` in app.js defines the five bottom-nav sections; Workshop, Journal and Character hold sub-tabs (segmented control, last one kept in `state.ui.sub`). Theme is `state.ui.theme` (`dark`|`light`|`auto`), applied by `applyTheme()`.
- **New page:** add `tabX()`, an entry in `RENDER`, and put its key into a `SECTIONS` entry (a sub-tab of Workshop/Journal/Character, or its own section). A filterable list also needs an `xList()` rendered into `<div id="list">` and an entry in `LIST_RENDER`.
- **Accessibility:** every interactive element must be at least 44x44px (pips and checkboxes use a larger hit area around a smaller visual), have an accessible name (`aria-label` where only a placeholder exists), and keep the `:focus-visible` ring. Text 4.5:1, big stats 7:1 in both themes; labels 13px minimum.
- **New filter:** store it in `state.ui.f[page][key]` through `F(page)`. Build it with `chips`/`fselect`/`fsearch`/`fcheck` and apply it inside `xList()`.
  - Search uses `matchQ(page, ...texts)`.
  - Typing in a filter re-renders only the list (keeps focus); chip clicks re-render the page.
- Data entries are built with small factory helpers (`L` in spells, `P` in plans, `F` in feats) and get an `id` from the name. Per-level numbers are 20-element arrays indexed with `at()`.
- Uses and spell slots are stored as "used" counts. Rests reset them in `rest()`.
- Naming: camelCase JavaScript, kebab-case CSS classes, 2-space indent, single quotes, semicolons.

## Known weak spots
- With network-first + skipWaiting, an open page can lazy-import a newer `spell-details.js` / `drive.js` than its running `app.js` until it reloads; the update banner (and the 30-minute `registration.update()` on return to the app) mitigates it.
- `js/app.js` is large (about 3540 lines) and mixes views, logic and actions. Splitting it (e.g. one module per tab) is reasonable, but **only do it when the user asks**.
- Tests are not run in CI; run `node tests/run.mjs` locally. Not covered: real Google account, real devices.
- Data lives per device and browser; the only sync is the optional Google Drive mirror (otherwise export/import).
- `confirm()`/`alert()` remain only for Delete everything and the import-failed alert; everything else (including the import confirmation) uses sheets. Casting-time tags depend on the lazy-loaded details, so the Spells list shows "Loading spell details…" briefly on first visit.
